## 2. NEW SURFACE

Every item traced to its ruling by number.

**`equity_<login>.dat` record layout** (V2-D8), serialized by new `AgEquitySerialize`, written through `AgAtomicWrite` (`Persist.mqh:112`, the persistence family's single writer), three lines:

```
AGEQUITY|1|<login>
E|<anchor epoch seconds>|<equity_peak, 8 decimals>
C|<FNV-1a checksum of the two lines above>
```

Field by field: magic `AGEQUITY`, distinct from `AGHALT`/`AGSTATE`/`AGFLOOR`/`AGPEAK` so no cross-read is possible (the `Persist.mqh:349-350` convention); format constant `AG_EQUITY_FORMAT_VERSION` starting at 1 (V2-D8, its own constant, no migration branch on the version 1 files); login in the header (V2-D8: login mismatch is CORRUPT_STATE equivalent per the 2026-07-30 FINAL, implemented as the same quarantine class the peak file uses, and per V2-D4 the outcome DEGRADES TO THE REALIZED PEAK, never to nothing and never to a lock, the equity file not being lock state); `E` record carrying the anchor (V2-D8: the anchor is stored in the record; a stale anchor makes the persisted value 0.00 for the current day) and the peak at `AG_STATE_MONEY_DIGITS` 8 decimals (`Persist.mqh:40` precedent, a convention noted as such); checksum line last (family convention, torn-write detector).

**Model and functions** (all new, in `Persist.mqh`, mirroring the peak block `:877-1212` function for function): `AG_EQUITY_FORMAT_VERSION`; globals `g_ag_equity_anchor`, `g_ag_equity_peak` (the in-memory running maximum of pnl, the value every breach comparison uses per V2-D3), `g_ag_equity_loaded` (never-loaded-never-written, inherited by name per V2-D8), `g_ag_equity_reconciled`, `g_ag_equity_last_written` (change detector for the write gate), `g_ag_equity_last_write` (write cadence stamp, local clock, A1 class); `AgEquityPath`, `AgEquitySerialize`, `AgEquitySave` (refuses while not loaded, V2-D8 inheritance), `AgEquityResetModel`, `AgEquityQuarantine` (free name via `AgStateQuarantinePath` `Persist.mqh:332-344`, no lock follows, degrade per V2-D4), `AgEquityLoad` (returns 0 loaded / 1 missing / 2 corrupt / 3 login mismatch, 2 and 3 handled identically).

## 5. OPEN QUESTIONS

Numbered V2-D15 onward. Closed options, no recommendation. Nothing below is decided by this plan, and the tasks that depend on each are parked in T12.

- **V2-D15. The scope of V2-D4's max() rule, and chosen=peak reachability.** V2-D4 reads "On every pass, and therefore on restart, the taken equity peak is max(persisted_equity_peak, reconstructed_realized_peak, in_memory_equity_peak)". Read as a per-pass assignment, the equity peak absorbs the realized peak on every pass, so `equity_level >= peak_level` always and `chosen=peak` becomes structurally unreachable except through a persisted-realized-file anomaly, joining `chosen=ratchet` as a finding; the acceptance row demanding `chosen=peak` observed once would then need reclassification. Read as the reconciliation-and-restart authority (the formula holds whenever evaluated, so restart needs no special code, with intraday rises coming from V2-D2 samples alone), a closure spike between two samples leaves the realized peak above every equity sample and `chosen=peak` is observable, which the four-valued V2-D7 field and the required row are consistent with. Options: (a) per-pass max, the realized term pulls the equity peak up every pass, chosen=peak reclassified as a finding; (b) reconciliation-scope max, intraday rise from samples alone, chosen=peak observable.
- **V2-D16. The equity file and model under a backward clock step.** V2-D8 inherits the stale-anchor rule for an EARLIER anchor (persisted reads 0.00 for the current day) and says nothing about a file or model anchor LATER than the window anchor, which is what a rewound clock produces. The version 1 peak holds and does not rewind (`backward_step_max`, `Persist.mqh:1120-1124`, `:1171-1186`), but that behaviour is not among the four items V2-D8 inherits by name. Options: (a) mirror the peak block, hold the later-anchored value, take the max at reconciliation, warn on its own cadence, never raise from a widened window; (b) treat any anchor other than the current one as not-current, persisted and model contributing 0.00.
- **V2-D17. The write on the pass that declares a lock.** The declaring pass returns at `AccountGuardian.mq5:829` before the cadence copy, and version 1 emits the lock level line UNCONDITIONALLY on that pass for exactly that reason. V2-D3's write gate, applied to the letter, can leave the in-memory high that triggered the lock unwritten (the pass may not be write-due), and after the lock the ACTIVE tail never runs again for that day; the cost is bounded, the equity peak playing no part in the locked window (V2-D11) and the value being discarded at the next rollover anyway, but the file then never records the high the day actually locked on. Options: (a) the letter of V2-D3, no write outside a due-and-changed pass, the declaring pass included, cost as stated; (b) the lock-level-line precedent, one unconditional write and raised line on the declaring pass.
- **V2-D18. Save timing at reconciliation and at rollover.** V2-D3's Issue line scopes itself to "the file write and the journal line for an equity peak rise". The version 1 peak block saves immediately at reconciliation (`Persist.mqh:1141`) and at rollover (`:1159`); save timing is not among V2-D8's named inheritances. Options: (a) mirror the peak block, one immediate save at reconciliation and one at rollover, the rise gate governing only rises; (b) the strict letter of V2-D3 extended to every write, reconciliation and rollover results reaching disk only on the next due-and-changed pass, at most one interval of exposure, the V2-D4 degrade bounding the loss.
